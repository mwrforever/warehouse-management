# 2026-08-12 库存管理模块端到端测试

> **对应细化 spec：** `docs/superpowers/specs/2026-08-12-inventory-spec.md`
> **执行工具：** playwright-cli；**前置依赖：** 系统管理 + 基础资料模块测试通过；采购模块至少完成「采购入库审核」链路（本测试的流水数据源），或使用测试种子直接注入已知库存。

## 1. 测试概述与业务流转

库存模块是**核心不变式**的载体，本测试重点验证：余额/流水展示、盘点全链路（盘盈/盘亏）、审核幂等、预警联动、余额=流水恒等式。

```
登录(admin) → 余额页核对基线库存 → 新建盘点单(加载账面数→录入实盘)
→ 保存草稿 → 审核(盘盈+盘亏) → 验证流水与余额变化 → 复核恒等式 → 预警状态验证
```

**数据基线（测试专用）**：测试开始前通过采购入库审核制造以下库存（数字精确）：

| 商品 | 仓库 | 库位 | 数量 | safety_min | safety_max |
|---|---|---|---|---|---|
| MAT-001 测试铝材(原料) | 主仓 | A-01 | 100 | 50 | 500 |
| SEMI-001 半成品A | 主仓 | A-01 | 30 | 10 | 200 |
| FIN-002 成品B | 主仓 | B-01 | 20 | 0 | 0 |

## 4. 失败处理说明（测试未通过时）

同系统管理模块测试文档 §4，另加本模块特有判定：

- **恒等式破坏（INV-04）**：直接判定为**核心缺陷**——事务缺失/双写不一致，按 `superpowers:systematic-debugging` 深挖 InventoryService，修复后必须重跑 INV-04/08/09/10 全链
- **审核幂等失败**：并发控制缺陷（缺行锁/状态判重），同为核心缺陷
- 修复遵循 superpowers 流程：先补 PHPUnit 核心测试（库存引擎 100% 覆盖是主 spec §10 硬性要求）再改代码，最后回归本文档
