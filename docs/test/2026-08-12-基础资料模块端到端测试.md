# 2026-08-12 基础资料模块端到端测试

> **对应细化 spec：** `docs/superpowers/specs/2026-08-12-master-data-spec.md`
> **执行工具：** playwright-cli；**前置依赖：** 系统管理模块测试通过（登录 + RBAC 可用）

## 1. 测试概述与业务流转

覆盖基础资料全部 8 个子模块：商品、分类、单位、仓库/库位、供应商、客户、工序、BOM。业务流转主线：

```
登录(admin) → 分类/单位(基础数据先行) → 仓库+库位 → 供应商/客户 → 工序
→ 商品(引用分类/单位，设安全库存) → BOM(引用成品+物料) → 删除保护验证
```

**业务依赖顺序说明**：分类/单位/仓库必须先建（商品引用）；BOM 必须等成品与原料商品建好（引用校验）；删除保护用例放在最后（需要先有引用关系）。

## 2. 前置条件与数据准备

| 依赖项 | 要求 |
|---|---|
| 环境 | 后端 `http://localhost:8000`、前端 `http://localhost:5173` 运行中；系统管理模块测试已通过 |
| 种子数据 | 分类「原材料」「成品」；单位「个/件/千克」；仓库「主仓」；商品 `RAW-001 铝材(原料)`、`FIN-001 成品A(成品)`；工序「下料」 |
| 登录 | 每个用例前 `playwright-cli state-load auth.json` 恢复 admin 登录态 |

**测试专用数据**（用例内创建，结束时清理）：分类「测试分类」、单位「测试单位」、仓库「测试仓」+ 库位「A-01」、供应商「测试供应商」、客户「测试客户」、工序「测试工序」、商品 `MAT-001/半成品A/SEMI-001/成品B`、BOM「BOM-FIN-001」。

## 3. 测试用例

### TC-MST-01 分类树与删除保护

**前置：** admin 已登录。

| # | 操作 | 预期请求与响应 | 通过条件 |
|---|---|---|---|
| 1 | 侧边栏「基础资料 → 分类」 | `GET /api/v1/categories`，响应 data 为树形（含 children 层级） | 树显示「原材料」「成品」两级 |
| 2 | 点击「新 建」，上级选「原材料」，名称「测试分类」，保存 | `POST /api/v1/categories`，请求体 `{"name":"测试分类","parent_id":1,"sort":1}`；响应 `{"code":0}` | 树中「原材料」下出现「测试分类」 |
| 3 | 点击「测试分类」行「删除」 | `DELETE /api/v1/categories/{id}`，响应 `{"code":0}` | 节点消失 |
| 4 | 对「原材料」执行删除（含子分类） | 响应 `{"code":1101,"message":"存在子分类，不可删除"}` | 红色提示出现，节点保留 |
| 5 | 对「成品」执行删除（被商品引用） | 响应 `{"code":1102,"message":"分类已被商品使用，不可删除"}` | 同上，删除按钮逻辑提示 |

**通过标准：** 树形展示正确、子分类/被引用删除被拒。

## 4. 失败处理说明（测试未通过时）

同 `docs/test/2026-08-12-系统管理模块端到端测试.md` §4 流程：

1. `playwright-cli screenshot --filename=docs/test/evidence/{tc编号}-fail.png` + `console` + `requests` 抓现场
2. 判定层级：接口层（响应不符 spec §4）→ 后端缺陷；UI 层（按钮/弹窗/校验缺失）→ 前端缺陷；环境层（种子/服务）→ 修正重跑
3. 修复遵循 superpowers：`systematic-debugging` 定位 → `test-driven-development` 先补测试再修 → 回归本文档全部用例及上游模块用例
4. **跨模块影响**：本模块数据被下游（库存/采购/销售/生产）引用，修复后需联动回归下游模块测试文档中引用本模块数据的用例
