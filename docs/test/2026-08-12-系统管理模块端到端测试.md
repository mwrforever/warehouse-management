# 2026-08-12 系统管理模块端到端测试

> **对应细化 spec：** `docs/superpowers/specs/2026-08-12-system-management-spec.md`
> **执行工具：** playwright-cli（浏览器自动化）；接口校验通过浏览器开发者网络面板（`playwright-cli requests`）与响应断言
> **测试日期：** 2026-08-12

## 1. 测试概述与业务流转

本测试文档覆盖系统管理模块全部功能：登录/登出、用户管理、角色管理（RBAC 权限分配）、字典管理。业务流转主线：

```
登录 → /auth/me 拉取权限 → 用户管理(增删改/分配角色) → 角色管理(勾选权限)
→ 用受限账号验证越权拦截 → 字典管理(增删改/取值) → 登出
```

测试按「业务依赖序」执行：**登录是全部用例的前置**，先测认证，再测用户/角色，最后字典。

## 2. 前置条件与数据准备

| 依赖项 | 要求 |
|---|---|
| 环境 | docker-compose MySQL 8.4 已启动；Laravel 后端运行于 `http://localhost:8000`；Vue 前端运行于 `http://localhost:5173` |
| 种子数据 | 已执行 `php artisan db:seed`：内置超级管理员 `admin / admin123`（拥有全部权限，角色 code=`admin`）；一个只读角色 `operator`（仅 `*.list` 权限） |
| 测试账号 | 用例执行过程中新建：`tester01 / Test@12345`；`limited01 / Test@12345`（仅 operator 角色） |
| 浏览器 | 无痕模式（避免历史登录态污染）；执行前 `playwright-cli open` 新建会话 |

**执行规则：** 每个用例前若未登录则先执行「TC-SYS-01 登录」；用例间通过 `playwright-cli state-save auth.json` / `state-load` 保留登录态。

## 3. 测试用例

### TC-SYS-01 登录（正常路径 + 异常路径）

**目标：** 正确凭证登录成功并跳转；错误凭证提示且不跳转；空表单拦截。

**前置：** 未登录状态（`playwright-cli cookie-clear` 后访问 `/login`）。

**步骤：**

| # | 操作 | 预期请求与响应 | 通过条件 |
|---|---|---|---|
| 1 | `playwright-cli goto http://localhost:5173/login` | 无 | 页面显示登录卡片：用户名、密码输入框、「登 录」按钮 |
| 2 | 点击「登 录」按钮（不填内容） | 前端表单校验拦截，**不发请求** | 用户名/密码输入框下方显示「请输入用户名/密码」红色校验提示，停留 `/login` |
| 3 | 用户名输入 `admin`，密码输入 `wrongpass`，点击「登 录」 | `POST http://localhost:8000/api/v1/auth/login`，请求体 `{"username":"admin","password":"wrongpass"}`；响应 `{"code":1001,"message":"用户名或密码错误"}` | 页面右上角红色 `ElMessage` 显示「用户名或密码错误」，URL 仍为 `/login`，`localStorage` 无 token |
| 4 | 密码改为 `admin123`，点击「登 录」 | 响应 `{"code":0,"data":{"token":"1|...","user":{...,"permissions":["user.list",...]}}}` | URL 跳转 `/dashboard`；`localStorage.getItem('token')` 非空；`/auth/me` 请求返回 `permissions` 含 `user.list`、`role.list` 等全部权限 |

**用例通过标准：** 步骤 2/3/4 全部符合预期。

## 4. 失败处理说明（测试未通过时）

当任一用例断言失败时，按以下流程记录并修复（遵循 superpowers 工作流）：

1. **记录失败现场**：`playwright-cli screenshot --filename=docs/test/evidence/{tc编号}-fail.png`；`playwright-cli console` 抓取浏览器 console 错误；`playwright-cli requests` 导出实际请求/响应
2. **判定失败层级**（写入测试结果报告）：
   - **接口层失败**：实际响应与文档预期不符（状态码/字段/错误 message）→ 属后端缺陷，用 `superpowers:systematic-debugging` 定位（复现 → 最小化 → 修复 → 回归）
   - **UI 层失败**：按钮/弹窗/提示未按预期出现 → 属前端缺陷，同样走 systematic-debugging
   - **环境层失败**：服务未启动/种子缺失/端口不通 → 修正前置条件后重跑该用例，不计入产品缺陷
3. **修复**：基于 `superpowers:test-driven-development`——先为失败行为补测试（PHPUnit 接口测试 / Vitest 组件测试），再实现修复，最后回归本测试文档全部用例
4. **回归**：修复后从失败用例的前置用例开始重放，确认业务链不中断
