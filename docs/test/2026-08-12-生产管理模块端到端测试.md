## 1. 测试概述与业务流转

生产模块是全系统最复杂链路，按业务顺序执行完整生产闭环：

```
建工单(FIN-002×10, BOM 展开) → 下达 → 开工 → 领料(原料-验证) → 工序1报工
→ 工序2委外(发出-回收+) → 末工序报工完成 → 成品入库(成品+ → 工单自动完成)
→ 退料冲销 → 工单关闭 → 边界拦截(超领/超收/虚报) → 幂等验证
```

**测试专用数据**：工单产品 FIN-002（成品B）；BOM：MAT-001×2/成品（基础资料测试已建，若清理需重建）；工序：下料(seq1)、测试工序→正式命名为「组装」(seq2)、「质检」(seq3)（用基础资料测试的工序若已删则重建 2-3 个）；供应商 SUP-001（委外用）；仓库主仓。**库存基线**：执行前记录 MAT-001、FIN-002 余额 P₁、F₁。

## 4. 失败处理说明（测试未通过时）

同库存/采购模块 §4。本模块特有判定：

- **PRD-03/07/09 库存数不符**：核心缺陷（InventoryService 方向/事务），先查事务包裹与方向常量
- **PRD-04 工序不自动推进**：报工服务状态机缺陷（累计判定/下一工序推进逻辑）
- **PRD-07 工单不自动完成**：成品入库后 completed_qty 回写与状态判定缺陷
- **PRD-06 委外回收不联动**：回收单双写（流水+委外状态）事务缺陷
- 修复流程：superpowers `systematic-debugging` 定位 → `test-driven-development` 补 PHPUnit（生产服务 100% 覆盖：状态机流转/库存双写/事务回滚）→ 全量回归本文档 + 库存模块恒等式
