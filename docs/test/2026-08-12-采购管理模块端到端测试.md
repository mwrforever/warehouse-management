# 2026-08-12 采购管理模块端到端测试

> **对应细化 spec：** `docs/superpowers/specs/2026-08-12-purchase-spec.md`
> **执行工具：** playwright-cli；**前置依赖：** 系统管理 + 基础资料 + 库存模块测试通过（供应商/商品/仓库存在，InventoryService 可用）。

## 1. 测试概述与业务流转

覆盖采购订单全生命周期与入库单执行链路，核心验证**审核后库存增加 + 订单状态联动 + 超量拦截**。

```
登录(admin) → 建采购订单(2 行: MAT-001×100、SEMI-001×50) → 审核
→ 从订单生成入库单(只入 MAT-001×60 → 部分入库) → 审核 → 验证库存+60
→ 再入库 MAT-001×40 + SEMI-001×50 → 全部入库 → 订单自动「已完成」
→ 超量入库拦截验证 → 订单关闭验证 → 幂等验证 → 金额一致性验证
```

**测试专用数据**：供应商「测试供应商」（基础资料测试已建，若被删则先重建：`SUP-001`）；商品 MAT-001（原料）、SEMI-001（半成品A）；仓库「主仓」库位 A-01。**基线**：MAT-001 余额 60（承接库存模块测试末态，实际以当时为准，测试中记录）。

### TC-PUR-01 采购订单创建（金额计算）

| # | 操作 | 预期请求与响应 | 通过条件 |
|---|---|---|---|
| 1 | 「采购管理 → 订单」点「新 建」 | 弹窗打开 | 抬头含供应商/日期；明细表格含「+ 添加明细行」 |
| 2 | 供应商选 SUP-001；添加行1：商品 MAT-001 数量 100 单价 5.00；行2：SEMI-001 数量 50 单价 10.00 | — | 行金额分别显示 500.00 / 500.00；底部合计 **¥1,000.00**（实时） |
| 3 | 添加行3：MAT-001（重复商品） | 前端即时提示「明细存在重复商品」 | 行被拒绝或标红，合计不变 |

## 4. 失败处理说明（测试未通过时）

同库存模块测试文档 §4 流程。本模块特有判定：

- **PUR-04/PUR-05 库存数不符**：核心缺陷（InventoryService 调用/事务回滚问题），优先排查：入库单审核事务是否包裹流水+余额+订单回写三写；修复后回归库存模块 TC-INV-04
- **状态联动失败（PUR-05）**：订单状态重算逻辑缺陷（received_qty 回写遗漏）
- **超量拦截失败（PUR-03）**：事务内订单剩余量校验缺失或竞态（无行锁），按核心缺陷处理
- 修复遵循 superpowers：`systematic-debugging` → `test-driven-development`（补 PHPUnit 采购服务测试）→ 回归本文档 + 库存模块文档
