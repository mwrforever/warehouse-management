## 1. 扫码入口绕过「原料禁售」前端过滤（口径不一致，后端已兜底）

- 涉及：`web/src/views/sales/OrdersView.vue`（scanAdd，约 96-113 行）、`web/src/views/sales/OutboundsView.vue`（scanAdd，约 136-152 行）
- 证据：商品下拉数据源仅成品/半成品，但扫码入口 `productApi.byBarcode(code)` 后直接 `form.items.push({ product_id: p.id, ... })`，无 `p.type === 'raw_material'` 过滤。
- 影响：扫原料条码可加入销售明细，保存时才被后端 422「原料商品不可销售」打回（`SalesOrderController::validateBusinessItems` 兜底）。无安全影响，仅前端校验口径不一致、错误暴露时机滞后。

## 2. 多处弹窗数据加载裸 await（未处理 rejection + 无错误提示）

- 涉及：`DictionariesView.vue`（openItems，约 192-197 行）、`WarehousesView.vue`（openLocations，约 270-274 行）、`BomsView.vue`（openItems，约 298-302 行）、`UsersView.vue`（onMounted 角色下拉，约 223-226 行）、`ProductsView.vue`（onMounted 分类/单位下拉，约 324-328 行）
- 证据：`await dictionaryApi.items(dict.id)` 无 try/catch；同文件其它函数均有 `catch → ElMessage.error`，风格不一致。
- 影响：网络失败时弹窗打开但列表空白、无提示，控制台出现未处理 Promise rejection。

## 3. vite 代理 target 用 localhost，与后端 127.0.0.1 绑定存在 IPv6 解析差异

- 涉及：`web/vite.config.ts:10`（`proxy: { '/api': { target: 'http://localhost:8000', changeOrigin: true } }`）vs `web/playwright.config.ts:7`（`php artisan serve --host=127.0.0.1 --port=8000`）
- 背景：playwright.config.ts 内注释已证明本项目真实踩过 IPv6/IPv4 绑定错位（"vite 默认绑定 IPv6 ::1，Playwright 探测 127.0.0.1 会超时"）。
- 影响：Windows/Node≥17 上 `localhost` 若优先解析为 `::1`，dev 代理连接 IPv4 后端会 ECONNREFUSED；CI（ubuntu，localhost→127.0.0.1）与本机当前环境不暴露。属环境相关潜在跨端风险。
- 建议：`target` 改为 `http://127.0.0.1:8000` 与后端一致。

## 4. 内置超管弱口令 admin123，无首次登录强制改密

- 涉及：`server/database/seeders/RbacSeeder.php:157-160`（`firstOrCreate(['username' => 'admin'], [... 'password' => 'admin123', 'status' => 1])`）
- 影响：bcrypt 存储但口令本身可爆破；admin 不可删除（1003 保护）。E2E 依赖该凭据（playwright 种子库），属测试/演示凭据；若部署生产需改密 + 强制改密机制。
- 建议：部署文档标注首次登录改密，或种子支持 `ADMIN_PASSWORD` 环境变量覆盖。

## 处理结论（2026-08-13 修复波次）

4 项全部修复：

1. **扫码绕过原料禁售过滤**：`OrdersView.scanAdd`/`OutboundsView.scanAdd` 命中条码后增加 `p.type === 'raw_material'` 拦截，提示「原料商品不可销售」，与后端 422 口径一致。
2. **弹窗数据加载裸 await**：5 处（DictionariesView.openItems / WarehousesView.openLocations / BomsView.openItems / UsersView.onMounted 角色下拉 / ProductsView.onMounted 分类单位下拉）补 try/catch + ElMessage.error，与同文件其它函数风格一致。
3. **vite 代理 localhost → 127.0.0.1**：`vite.config.ts` proxy target 改为 `http://127.0.0.1:8000`，与后端绑定地址一致，消除 Windows/Node≥17 下 localhost 优先解析 ::1 的连接拒绝风险。
