## 二、偏离问题区

### D-1【完全偏离】§2.2.1 写操作未经 Service、控制器直接 DB::transaction 与写库【核验:✅真实】
- **条款**：「写操作必须经 Service 并在 Service 内声明事务边界；控制器禁止 DB::transaction 与写库。」
- **现状**：28 个控制器中 25 个直接写库；13 个控制器共 53 处 `DB::transaction`。核心业务（状态机流转、金额/数量计算、锁行校验、回写）大量落在控制器：
  - `server/app/Http/Controllers/Api/PickListController.php:135/221/257/281/381`（领料 CRUD/审核/发料全流程，含锁序与 issued_qty 回写）
  - `server/app/Http/Controllers/Api/PurchaseInboundController.php:341-431`（入库审核核心事务）
  - `server/app/Http/Controllers/Api/OutsourcingController.php:144/271/309/339/455/614`（6 处事务：委外单/回收/退回）
  - `server/app/Http/Controllers/Api/ProductionOrderController.php`（7 处事务：下达/开工/完工/关闭）
  - 其余：CheckController(4)、BomController(3)、FinishedInboundController(4)、SalesOrderController(5)、SalesOutboundController(4)、PurchaseOrderController(5)、ReturnListController(4)、OperationReportController(2)、ProductController(1)；直接 create/update/delete 的还有 AuthController:41/50、CategoryController:67/102/119、DocumentNumberConfigController:50、User/Role/Supplier/Unit/Warehouse/Customer/Process/Dictionary 等控制器。
  - Service 层仅 10 个，只覆盖部分域（InventoryService/RoutingService/PurchaseOrderService 等）。
- **偏离程度**：完全（方向相反：分层职责整体落在控制器）。
- **修复方向（最小改动）**：按单据域分批将控制器事务块下沉为 Service 方法（优先核心单据审核/发料/退回路径），控制器保留编排与响应；其余主数据 CRUD 可后置。与 D-2/D-13 一并规划，避免二次搬迁。

### D-2【完全偏离】§2.2.2 校验未集中在 FormRequest【核验:✅真实】
- **条款**：「校验集中在 FormRequest；禁止控制器内散落大段手工校验。」
- **现状**：控制器内 47 处 `$request->validate`（含封装的 validatePayload 私有方法）+ 业务校验私有方法；`server/app/Http/Requests/` 仅 3 个类（RoleRequest/UserStoreRequest/UserUpdateRequest，只被 User/Role 控制器使用）。
  - 代表：`PickListController.php:405-417`（validatePayload）、`PurchaseInboundController.php:435-449`、`CategoryController.php:51-56/78-83`、`SalesOrderController.php:326` 附近等。
- **偏离程度**：完全（体系性落在控制器，FormRequest 层近缺失）。
- **修复方向**：随 D-1 下沉时同步将各 validatePayload 迁为 FormRequest（rules + 白名单），控制器签名改注入；业务规则类校验（状态/剩余量）留在 Service。

### D-3【完全偏离】§4.1.2（联动 §4.1.1 数量口径）浮点参与数量比较与累加【核验:✅真实】
- **条款**：「浮点参与金额、数量比较或累加的任何写法（`$a * $b`、`>=` 直接比较）均视为缺陷。」
- **现状**：
  - **核心库存引擎浮点运算**：`server/app/Services/InventoryService.php:48`（`$quantity = (float) $m['quantity']`）、`:58`（`(float) $balance->quantity < $quantity` 出库充足性比较）、`:91`（`(float) $balance->quantity + $direction * $quantity` 余额浮点累加）——全系统唯一库存变动入口使用浮点。
  - **盘点浮点差值**：`CheckController.php:273`（`round((float)$actual - (float)$book, 2)`）、`:288`（`abs((float)$balance->quantity - (float)$item->book_qty) > 0.005`）。
  - **数量/单价格式校验浮点比较 19 处**（十进制二进制误差下 `0.1+0.2` 类边界存在误判风险）：PurchaseOrderController.php:354/357、SalesOrderController.php:355/358、SalesOutboundController.php:486/489、OutsourcingController.php:110/241/447、FinishedInboundController.php:351、ProductionOrderController.php:96/300、ReturnListController.php:347、PickListController.php:428、OperationReportController.php:43/46、CheckController.php:106/193。
  - 对照：单据层数量比较均已正确用 bcmath（PickListController.php:322-330、PurchaseInboundController.php:381-385），唯独引擎与校验层漂移。
- **偏离程度**：完全（铁律条款，核心引擎违规）。
- **修复方向**：InventoryService 改为 bcmath 字符串运算（quantity 以 `bcadd/bccomp` 处理，余额写出统一 `bcadd(...,2)` 归一）；校验类 `(float)$x <= 0` 改 `bccomp((string)$x, '0', 2) <= 0`（正则已限两位小数，字符串安全）。

### D-4【部分偏离】§4.1.1 金额存储形态与前端换算【核验:✅真实】
- **条款**：「金额一律分单位整数 + bcmath 运算。」
- **现状**：后端计算链路合规（PurchaseOrderService.php:18-37 bcmul/bcadd；CostPriceService.php:57 bcadd 归一）；但金额列为 `decimal(14,2)` 而非整数（注释却标注「（分）」）：`database/migrations/2026_08_12_110000_create_purchase_tables.php:19/34/36/49/63/64`、`2026_08_13_100000_create_sales_tables.php:20/35/37/50/64/65`。§6.2 允许「decimal 或分单位整数」，与 §4.1.1 冲突（宪法以更严格者为准应为整数）。前端换算用浮点：`web/src/views/purchase/OrdersView.vue:57/67/135/174`（`Number(qty)*Number(price)`、`Math.round(...*100)`）、sales/OrdersView.vue:58、sales/OutboundsView.vue:75 同类。
- **偏离程度**：部分（bcmath 主链路合规；存储形态与前端算术不符）。
- **修复方向**：评审定口径——若维持 decimal(14,2) 分单位，在宪法修订处备案豁免；前端行金额改「分单位整数运算 + formatYuan 展示」，消除浮点乘法。

### D-5【部分偏离】§1.5 / §3.1.3 魔法状态值与缺失 STATUS_* 常量【核验:✅真实】
- **条款**：「禁止魔法值：状态码……必须使用命名常量（后端模型常量 STATUS_*）」（§1.5）；「模型状态常量以 STATUS_ 开头」（§3.1.3）。
- **现状**：`BomController.php:135`（`if ($status === 1)`）、`:138`（`->update(['status' => 0])`）；`AuthController.php:36`（`$user->status !== 1`）。11 个含 status 字段的模型无 STATUS_* 常量：BomHeader、Category、Customer、DictionaryItem、Location、Process、Product、Supplier、Unit、User、Warehouse（脚本扫描 app/Models 全量）。
- **偏离程度**：部分（单据类模型常量齐全，主数据/用户类缺失）。
- **修复方向**：为上述模型补 `STATUS_ENABLED/DISABLED`（或语义对应）常量并替换控制器裸值。

### D-6【部分偏离】§3.3.2 索引命名无 idx_/uniq_ 前缀【核验:✅真实】
