# CSV 导出全量内存：注释声称流式不占内存，实际全量装载 + 全量拼串

- 发现日期：2026-08-13
- 严重级别：中（资源，数据量大时内存线性增长）
- 状态：已修复（2026-08-13 修复波次，提交 1dab666（PR #8 已合入 main））
- 涉及文件：`server/app/Http/Controllers/Api/InventoryController.php`

## 问题描述

`exportBalances` 先 `$this->balanceQuery($request)->get()` 一次性装载全部余额行，再以 `$csv .=` 循环拼接完整 CSV 字符串，最后才交给 `response()->stream()` 输出（`InventoryController.php:29-46`）。第 44 行注释"大文件导出不占内存"与实际实现不符——**内存随行数线性增长**，`stream` 只包装了已构建好的字符串，未起到流式作用。

## 证据

```php
// InventoryController.php:29-46
$rows = $this->balanceQuery($request)->get();
$csv = "\xEF\xBB\xBF"."商品编码,商品名称,仓库,库位,数量,下限,上限,状态\n";
foreach ($rows as $r) {
    ...
    $csv .= implode(',', array_map(...))."\n";
}
// 用流式响应输出 CSV（...且大文件导出不占内存）
return response()->stream(function () use ($csv): void {
    echo $csv;
}, 200, [...]);
```

## 影响

- 商品×库位规模大时（数千行以上）导出接口内存占用线性增长，存在 OOM 风险；
- 非泄漏（请求结束释放），但语义与注释矛盾。

## 建议修复方向

- 流式生成：`response()->stream` 内直接 `fputcsv` 逐行输出 + `ob_flush`；
- 或对查询结果分块（`chunk`/游标）边取边写，避免整表驻留内存。

## 处理结论（2026-08-13 修复波次）

**确认存在，已修复。** 修复方案（InventoryController::exportBalances）：

1. 移除 `->get()` 全量装载与 `$csv .=` 全量拼串；
2. `response()->stream` 回调内 `balanceQuery($request)->cursor()` 游标逐行读取 + `fputcsv` 逐行写出（内存与总行数无关）；
3. 保留 UTF-8 BOM 与无引号中文表头原样输出（导出测试按精确表头断言）；数据行沿用 fputcsv 默认全字段引号包裹，与原格式一致。

配套验证：`InventoryBalanceTest` 两条导出测试（BOM/表头/行内容/状态列）保持全绿。全量 375 单测、phpstan 全绿。
