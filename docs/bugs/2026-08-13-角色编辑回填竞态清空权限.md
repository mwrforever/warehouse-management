# 角色编辑回填竞态：权限树未加载完时点编辑，保存后角色权限被静默清空

- 发现日期：2026-08-13
- 严重级别：中-高（数据丢失：角色权限被全量重挂为空）
- 状态：已修复（2026-08-13 修复波次，提交号待补）
- 涉及文件：`web/src/views/system/RolesView.vue`

## 问题描述

`onMounted` 中 `load()`（角色列表）与 `loadPermissions()`（权限树）并行执行，且 `load()` 未 await。`openEdit()` 依赖 `treeData`（权限树）构建 code→id 映射来回填勾选；若列表先返回、权限树未完成，用户立即点「编辑」，映射全部失败 → `checkedKeys` 为空 → `setCheckedKeys([])` → 弹窗权限树全不勾选，直接保存以空 `permission_ids` 全量重挂 → **该角色全部权限被静默清空**。

与 `BomsView` 曾在 `a0ff020` 修复的「编辑回填竞态（先取明细后开弹窗）」同构。

## 证据

```ts
// RolesView.vue onMounted：load 与 loadPermissions 并行
onMounted(async () => {
  load()               // 列表请求未 await，与 loadPermissions 并行
  await loadPermissions()   // treeData 在此才填充
})

// RolesView.vue openEdit：treeData 为空时映射全部失败
const codeToId = new Map<string, number>()
treeData.value.forEach((g) =>
  g.children?.forEach((p) => codeToId.set(p.code as string, p.id as number)),
)
checkedKeys.value = row
  ? row.permissions.map((code) => codeToId.get(code)).filter((id) => id !== undefined)
  : []
...
treeRef.value?.setCheckedKeys(checkedKeys.value)
```

## 影响

- 竞态窗口内编辑任意角色并保存 → 该角色权限被清空（所有成员失去对应功能权限）；
- 后端 `RoleController::update` 对空 `permission_ids` 执行 `sync([])`，无"至少保留一项"等校验，静默生效。

## 建议修复方向

- `openEdit` 在 `treeData` 为空时先 `await loadPermissions()`（或缓存 Promise 复用）；
- 或编辑弹窗打开时对 treeData 判空并加载完成后再置可见；
- 后端可加防御：`permission_ids` 空数组时拒绝保存（除非角色本就无权限）。

## 处理结论（2026-08-13 修复波次）

**确认存在，已修复。** 修复方案（RolesView.vue）：

1. `loadPermissions()` 改为 Promise 缓存（`permTreePromise`）——列表与权限树并行加载，`onMounted` 与 `openEdit` 复用同一请求，失败清缓存可重试；
2. `openEdit` 回填前 `await loadPermissions()`：权限树未就绪时等待，加载失败则阻断弹窗并提示「权限清单加载失败，请重试」（防空树保存清空角色权限）；
3. `onMounted` 预加载失败静默（不阻塞列表，弹窗打开时会重新请求并提示）。

后端防御（permission_ids 空数组拒绝保存）未做：无法区分「故意清空权限」与竞态清空，前端修复已闭合竞态窗口，不引入误伤。
