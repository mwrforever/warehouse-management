# 仓库/库位删除保护缺口：被草稿盘点单引用时删除 → FK RESTRICT → 500

- 发现日期：2026-08-13
- 严重级别：中（运行错误：裸 500）
- 状态：已修复（2026-08-13 修复波次，提交号待补）
- 涉及文件：`server/app/Http/Controllers/Api/WarehouseController.php`、`server/database/migrations/2026_08_12_090000_create_inventory_tables.php`、`2026_08_14_110000_create_production_documents_tables.php`

## 问题描述

`WarehouseController` 的仓库/库位删除守卫只查 3 张表：

- 仓库：`inventory_balances`、`purchase_inbounds`、`sales_outbounds`（`WarehouseController.php:95-97`）
- 库位：`inventory_balances`、`purchase_inbounds`、`sales_outbounds`（`WarehouseController.php:154-156`）

漏掉同样 `restrictOnDelete` 的：`inventory_movements`（warehouse_id/location_id）、`inventory_checks`（warehouse_id，**盘点草稿必选仓库，可达**）、`inventory_check_items`（location_id，盘点明细库位，可达）、`pick_lists`/`pick_list_items`/`return_lists`/`return_list_items`/`outsourcing_orders`/`outsourcing_receipts`/`finished_inbounds`（生产单据，控制器未实现，暂不可达）。

可达路径：仓库/库位被**草稿盘点单**引用（盘点单创建即写入 inventory_checks.warehouse_id 与 items.location_id）→ 删除仓库/库位时守卫放行 → FK RESTRICT → 未捕获 QueryException → 500。

## 证据

```php
// WarehouseController.php:95-97 —— 守卫仅 3 表
if (
    DeletionGuard::referenced('inventory_balances', 'warehouse_id', $warehouse->id)
    || DeletionGuard::referenced('purchase_inbounds', 'warehouse_id', $warehouse->id)
    || DeletionGuard::referenced('sales_outbounds', 'warehouse_id', $warehouse->id)
) { return $this->fail(1106, '仓库存在库存，不可删除'); }

// 迁移 2026_08_12_090000:49 —— 盘点单仓库 FK 为 RESTRICT
$table->foreignId('warehouse_id')->constrained('warehouses')->restrictOnDelete()->comment('盘点仓库');
```

## 影响

- 有草稿盘点单的仓库/库位删除接口 500，无业务提示；
- 生产单据表上线后缺口扩大（领料/退料/委外/成品入库 8 表全部 restrict）。

## 建议修复方向

- 仓库/库位守卫补齐全部 restrictOnDelete 引用表（含生产单据 8 表）；
- 或与商品删除保护同策：删除保护清单从迁移集中导出，避免逐控制器手抄遗漏。

## 处理结论（2026-08-13 修复波次）
