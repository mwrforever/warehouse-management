# 库存种子非幂等：重复 db:seed 使基线库存与流水重复累加

- 发现日期：2026-08-13
- 严重级别：中-高（数据完整性：余额/流水翻倍，破坏 E2E 精确断言与测试环境）
- 状态：已修复（2026-08-13 修复波次，提交号待补）
- 涉及文件：`server/database/seeders/InventorySeeder.php`

## 问题描述

`InventorySeeder::run()` 对商品/库位/分类等使用 `firstOrCreate`（幂等），但对库存基线**无条件调用** `$this->inbound($svc, ...)`，后者直接走 `InventoryService::apply()` 累加余额并写流水（无幂等保护）。重复执行 `php artisan db:seed`（或 migrate:fresh 后再次 seed）会使 MAT-001 100→200、SEMI-001 30→60、FIN-002 20→40，且流水重复落库。

E2E（TC-INV-01 等）依赖精确数值断言，一旦种子被重复执行（非 migrate:fresh 重建流程），余额断言全部失败且不易排查。

## 证据

```php
// InventorySeeder.php:56-58 —— run() 内无条件入账
$this->inbound($svc, $mat, $a01, 100);
$this->inbound($svc, $semi, $a01, 30);
$this->inbound($svc, $fin, $b01, 20);

// InventorySeeder.php:62-77 —— inbound() 直接走统一引擎（无条件累加+写流水）
private function inbound(InventoryService $svc, Product $product, Location $location, float $qty): void
{
    $svc->apply([[...]], null);
}
```

## 影响

- 测试/开发库余额与流水翻倍，E2E 数值断言失效；
- 若被误当初始化脚本在生产执行两次，库存虚增。

## 建议修复方向

- `inbound()` 前检查对应商品×仓库×库位的余额行是否已存在（存在则跳过，与 firstOrCreate 同语义）；
- 或按 `source_no = 'PO'.date('Ymd').'-SEED'` + `source_type='purchase_inbound'` 查重；
- 或 run() 入口整体判空（`InventoryBalance::exists()` 时跳过库存段）。

## 处理结论（2026-08-13 修复波次）

**确认存在，已修复。** 修复方案：`inbound()` 入口按 商品×仓库×库位 检查 `InventoryBalance` 余额行，已存在（重复 db:seed）则跳过入账，与其余 firstOrCreate 同幂等语义；不写流水。

配套测试：`InventoryStructureTest::test_inventory_seeder_is_idempotent`——种子二次执行后 MAT-001 余额仍为 100、流水条数不增。全量 375 单测全绿。
