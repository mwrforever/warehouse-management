### BF-1【中】工序网络「打开委外页」携带 `?keyword=单号` 跳转，但委外页不消费 keyword 参数——"按单号定位"功能名存实亡【核验:✅真实】

- **等级**：中　**分类**：④ 不符合项目宪法 / ② 数据丢失（联动定位失效）
- **引入提交**：`d7d3acb`（PR#33 "feat(outsourcing): 工序网络委外节点查看委外单并跳转"）
- **位置**：
  - 跳转发起：`web/src/views/production/OrdersView.vue:850`（`router.push(\`/production/outsourcings?keyword=${row.no}\`)`）
  - 跳转目标：`web/src/views/production/OutsourcingsView.vue:56`（`defaultQuery: { keyword: '', ... }`）、`:587-602`（onMounted 仅读取 `route.query.order_id`，未读 keyword）
- **证据**：

  ```ts

  @click="router.push(`/production/outsourcings?keyword=${row.no}`)"
  ```

  ```ts

  search()
  ...
  const orderId = Number(route.query.order_id)
  ```

  全库 grep `route.query` 确认：仅 FinishedInbounds/Reports/Picks/Outsourcings/Returns 读 `order_id`、MovementsView 读 `product_id/warehouse_id/date_from/date_to`，**无任何页面消费 `keyword` 查询参数**。E2E `outsourcing.spec.ts` TC-OS-04 对该跳转仅断言 `toHaveURL(/outsourcings\?keyword=/)` 与"行存在"——自建数据为最新单（id 倒序必在第 1 页），未断言"其余单被过滤"，测试无法暴露该缺陷。

- **建议修复方向**：OutsourcingsView onMounted 参照 MovementsView（`MovementsView.vue:183-194`）的预填模式：`const kw = route.query.keyword; if (kw) query.keyword = String(kw)` 后再 `search()`；并同步补 E2E 断言"过滤后仅含目标单"。

### BF-5【低】分类/工序/编号规则三页 load() 无 catch：首屏加载失败静默空白页 + unhandled rejection【核验:✅真实】

### BF-7【低】委外/工序接口契约类型声明 number、后端实际返回 decimal 字符串（quantity/received_qty/issued_qty/returned_qty/qualified_qty/hours 等）【核验:✅真实】

- **等级**：低（当前消费点已防御性 Number() 包裹，属潜伏陷阱而非现行错账）　**分类**：④ 宪法 5.7（接口类型定义与后端响应结构一致）
- **位置与证据**：
  - 前端声明 number：`web/src/api/production.ts:207`（`OutsourcingItem.quantity`）、`:209`（received_qty）、`:236-250`（detail 的 quantity/received_qty 与 items 的 required_qty/issued_qty/returned_qty）、`:37-39/:57-59`（`ProductionOperation`/`OperationGraphNode` 的 qualified_qty/defective_qty/hours）；
  - 后端为字符串：`server/app/Models/OutsourcingOrder.php:55`（`'quantity' => 'decimal:2'`）、`OutsourcingOrderItem.php:29-31`（三字段 decimal:2）、`WorkOrderOperation.php:46-48`（三字段 decimal:2）；`OutsourcingController::index/show` 直接透传模型属性（`'quantity' => $o->quantity`）、`received_qty` 为 `bcadd(...)` 字符串——JSON 实为 `"6.00"` 形态；
  - 对照组证明团队已知该口径：`api/dashboard.ts:5-11` 全部声明为 `string`（注释"金额/数量/进度均为后端输出的字符串"）；`RoutingService::graph` 则显式 `(float)` 强转返回数字。唯独委外/工序域两头都没对齐。

- **建议修复方向**：与 dashboard.ts 对齐——production.ts 相关字段声明改 `string`（或后端 graph 同款 `(float)` 归一），二选一全链路统一。
