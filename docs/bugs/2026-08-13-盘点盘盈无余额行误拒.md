# 盘点盘盈误拒：从未入库的商品无余额行，审核被 1206「库存已变动」错误拒绝

- 发现日期：2026-08-13
- 严重级别：中（功能缺陷，误导性拒绝）
- 状态：不存在（核实判定——现行为一致性设计而非缺陷；审查描述的 1206 路径不可达，本次仅标注。**用户 2026-08-13 裁决：账外盘盈功能暂不做**；如需支持按下方「处理结论」改动点清单另行立项）
- 涉及文件：`server/app/Http/Controllers/Api/CheckController.php`、`server/app/Services/InventoryService.php`、`web/src/views/inventory/ChecksView.vue`

## 问题描述

`InventoryBalance` 余额行只在首次入库时创建（`InventoryService.php:66-76`），从未入过库的商品**没有余额行**。`CheckController::approve` 对 `! $balance` 直接抛 1206「库存已变动，请重新盘点」（`CheckController.php:282`）。

预填接口 `autoBooks` 只列出现有余额行，但前端支持**扫码/手动添加任意商品**（`ChecksView.vue:95,359`），后端 `validatePayload` 也放行任意 `exists:products,id` 商品——因此对无余额行商品做**合法盘盈**（实盘 > 0）必被 1206 拒绝，且错误信息误导（并非"库存已变动"）。

## 证据

```php
// CheckController.php:282 —— 无余额行直接拒绝
if (! $balance || abs((float) $balance->quantity - (float) $item->book_qty) > 0.005) {
    throw new InventoryException('库存已变动，请重新盘点', 1206);
}

// InventoryService.php:66-76 —— 余额行仅入库时创建
if (! $balance) {
    $balance = InventoryBalance::create([...]);
}
```

## 影响

- 合法盘盈业务被阻断，用户收到错误诊断；
- 不涉及数据丢失（拒绝而非错误写入）。

## 建议修复方向

- 无余额行时按 `book_qty=0` 处理（盘盈方向由 `InventoryService::applyOne` 自动创建余额行，本就支持）；
- 或 `approve` 对 `! $balance && diff > 0` 走盘盈创建分支，仅 `diff < 0`（盘亏）时拒绝。

## 处理结论（2026-08-13 复核）

**问题不存在（现行为有意设计），本次标注不改代码。** 核实结论与审查描述不符：

1. **审查所述「必被 1206 拒绝」路径不可达**：无余额商品在 `CheckController::store/update`（:110-116、:194-200）即被 1205「商品在该仓库无库存，无需盘点」拦截（消息准确、有专属业务码），根本进不了 `approve`；`approve` 的 `! $balance` 分支是防御性代码——余额行只有创建没有删除路径，账面快照存在时余额行不可能消失。
2. **前端同口径拦截**：`ChecksView.vue` 扫码入口对无余额商品提示同文案（与后端一致），并非「前端放行、后端误拒」。
3. **测试锁定该设计**：`CheckTest::test_store_rejects_product_without_balance_with_1205` 与 E2E（inventory.spec.ts，RAW-001 无库存 → 1205）均显式断言「无余额商品不可录盘」——这是建模块时的一致性设计决策（盘点范围=有账面余额的库存），不是遗漏。

结论：现行为「前后端 + 测试一致锁定的设计」，无误导性拒绝。若业务上需要「账外资产盘盈」（无余额商品按 book_qty=0 盘盈建账），属新增功能需求而非缺陷修复，需产品确认后另行立项（届时须同步调整 1205 用例与 autoBooks 预填逻辑）。
