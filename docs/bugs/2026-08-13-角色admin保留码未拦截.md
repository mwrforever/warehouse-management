# 角色 admin 保留码未拦截：可创建第二个 admin 角色架空删除保护

- 发现日期：2026-08-13
- 严重级别：中-高（权限）
- 状态：已修复（2026-08-13 修复波次，提交 1dab666（PR #8 已合入 main）；直接"创建第二个 admin 角色"路径经核实不成立，修复的是"改名架空"路径）
- 涉及文件：`server/app/Http/Requests/RoleRequest.php`、`server/app/Http/Controllers/Api/RoleController.php`

## 问题描述

`RoleRequest` 对角色 `code` 仅有 `required|string|max:50|unique` 校验，**未拦截 `admin` 保留码**：持有 `role.create` 权限的用户可创建第二个 `code='admin'` 的角色。

`RoleController::destroy` 的"至少保留一个管理员角色"保护条件是 `Role::where('code', 'admin')->count() === 1`（`RoleController.php:59-63`）——存在第二个 admin 角色时该保护被架空。

## 证据

```php
// RoleRequest.php:26 —— 无保留码黑名单
'code' => ['required', 'string', 'max:50', Rule::unique('roles', 'code')->ignore($this->route('role'))],

// RoleController.php:59-63 —— 仅"唯一 admin"时保护生效
if ($role->code === 'admin' && Role::where('code', 'admin')->count() === 1) {
    return $this->fail(1007, '至少保留一个管理员角色');
}
```

## 影响

- 单独影响有限（新角色不会被自动分配），但与「admin 提权」组合（`user.update` 自挂角色）构成完整提权链；
- 第二个 admin 角色破坏"唯一 admin"不变量，`RbacSeeder` 的 `firstOrCreate(['code' => 'admin'])` 语义被扰动。

## 建议修复方向

- `RoleRequest` 增加 `not_in:admin`（或保留码清单）校验；
- 或将 `roles.code` 的 admin 唯一性改为数据库层约束 + 事务内检查。

## 处理结论（2026-08-13 修复波次）

**部分成立，已修复。** 核实结论：

- 「直接创建第二个 code='admin' 的角色」**不成立**：`roles.code` 有数据库唯一索引 + `Rule::unique` 双保险，重复 admin 编码在建/改时必 422/DB 冲突。
- 「改名架空」路径**成立**：`RoleRequest` 的 unique 规则 `ignore($this->route('role'))` 允许把内置 admin 角色的 code 改出 'admin'（如 boss），再新建 code='admin' 的角色——此时唯一约束放行，删除保护（`RoleController::destroy` 的 `code === 'admin'` + count===1）与中间件放行（`EnsurePermission` 按 code='admin'）均被架空。

修复方案（RoleRequest）：

1. 更新内置管理员角色时 code 锁定 `Rule::in(['admin'])`（不可改出）；
2. 新建/更新其他角色时 `Rule::notIn(['admin'])`（不可占用保留码，与唯一约束双重保险）。

配套测试：`RoleManagementTest` 新增 4 条（新建占用 admin → 422；普通角色改名占用 admin → 422；内置角色改出 → 422；内置角色保持编码可正常更新名称/权限）。全量 375 单测、phpstan、pint、phpcs 全绿。
