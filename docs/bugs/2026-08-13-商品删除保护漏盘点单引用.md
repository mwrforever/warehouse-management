# 商品删除保护漏表：被草稿盘点单引用时删除 → FK RESTRICT → 500

- 发现日期：2026-08-13
- 严重级别：中-高（运行错误：裸 500 而非业务码 1116）
- 状态：已修复（2026-08-13 修复波次，提交 1dab666（PR #8 已合入 main））
- 涉及文件：`server/app/Http/Controllers/Api/ProductController.php`、`server/database/migrations/2026_08_12_090000_create_inventory_tables.php`、`2026_08_14_110000_create_production_documents_tables.php`

## 问题描述

`ProductController::destroy` 的引用守卫（`ProductController.php:154-160`）覆盖 9 张表，但漏掉同样对 `product_id` 声明 `restrictOnDelete` 的 4 张表：

- `inventory_check_items`（盘点单明细，可达：盘点草稿可扫码/手动添加任意商品，`CheckController` store 校验仅 `exists:products,id`）
- `pick_list_items` / `return_list_items` / `finished_inbound_items`（生产单据明细，控制器未实现，暂不可达）

可达路径：商品被**草稿**盘点单明细引用（尚无流水/余额，守卫全部放行）→ `$product->delete()` 触发外键 RESTRICT → 未捕获 `QueryException` → 裸 500，而非 1116「商品已被业务单据使用，不可删除」业务提示。

## 证据

```php
// ProductController.php:154-160 —— 守卫清单缺失 inventory_check_items 等
$referencedByOther = DeletionGuard::referenced('inventory_movements', 'product_id', $product->id)
    || DeletionGuard::referenced('purchase_order_items', 'product_id', $product->id)
    || ...
    || DeletionGuard::referenced('production_order_materials', 'material_id', $product->id);

// 迁移 2026_08_12_090000:60 —— 盘点明细商品 FK 为 RESTRICT
$table->foreignId('product_id')->constrained('products')->restrictOnDelete()->comment('商品');
```

## 影响

- 商品被草稿盘点单引用时删除接口 500，前端收到原始错误而非业务码提示；
- 生产单据表上线后（领料/退料/成品入库控制器实现）缺口扩大。

## 建议修复方向

- `ProductController::destroy` 守卫补上 `inventory_check_items`、`pick_list_items`、`return_list_items`、`finished_inbound_items` 四表；
- 或统一策略：删除保护清单以"全部 restrictOnDelete 外键表"为准，从迁移集中导出（如 `DeletionGuard` 加表清单常量）。

## 处理结论（2026-08-13 修复波次）

**确认存在，已修复。** 核实补充：审查时判定"生产单据控制器未实现、暂不可达"，但生产模块此后已上线（PickList/ReturnList/FinishedInbound 控制器与路由均已存在），4 张表现已全部可达，问题影响面按当前代码为"可达 500"。

修复方案：`ProductController::destroy` 守卫补齐 `inventory_check_items`、`pick_list_items`、`return_list_items`、`finished_inbound_items` 四表（未建表时 DeletionGuard 自动放行，与既有"建后自动生效"机制一致）。

配套测试：`ProductTest` 新增 4 条（盘点明细/领料明细/退料明细/成品入库明细引用 → 1116）。全量 375 单测全绿。
