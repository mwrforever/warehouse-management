# 供应商删除保护漏表：委外加工单上线后删除供应商 → FK RESTRICT → 500

- 发现日期：2026-08-13
- 严重级别：低（登记时判定不可达；复核时委外控制器已上线，已升级为可达）
- 状态：已修复（2026-08-13 修复波次，提交 1dab666（PR #8 已合入 main））
- 涉及文件：`server/app/Http/Controllers/Api/SupplierController.php`、`server/database/migrations/2026_08_14_110000_create_production_documents_tables.php`

## 问题描述

`SupplierController::destroy` 守卫仅查 `purchase_orders`、`purchase_inbounds`（`SupplierController.php:93-94`），漏掉 `outsourcing_orders.supplier_id`（`restrictOnDelete`，迁移 110000 第 71 行）。

当前 `outsourcing_orders` 无控制器/无写入路径，问题不可触发；但生产委外模块实现后（Task 计划内），仅被委外加工单引用的供应商将删除失败并抛裸 500。

## 证据

```php
// SupplierController.php:93-94 —— 无 outsourcing_orders 检查
if (
    DeletionGuard::referenced('purchase_orders', 'supplier_id', $supplier->id)
    || DeletionGuard::referenced('purchase_inbounds', 'supplier_id', $supplier->id)
) { return $this->fail(1109, '供应商已被采购单据使用，不可删除'); }

// 迁移 2026_08_14_110000:71 —— 委外单供应商 FK 为 RESTRICT
$table->foreignId('supplier_id')->constrained('suppliers')->restrictOnDelete()->comment('委外供应商');
```

## 影响

- 当前无影响（表空）；
- 委外模块上线后：删除被引用的供应商 → 500。

## 建议修复方向

- 委外模块实现时同步在 SupplierController 补 `outsourcing_orders` 守卫；
- 或本轮即补（守卫对空表无副作用）。

## 处理结论（2026-08-13 修复波次）

**确认存在，已修复。** 核实补充：委外控制器（OutsourcingController）与路由已在生产模块上线，`outsourcing_orders` 已有写入路径，原「不可达」判定过期——本轮即补。

修复方案：`SupplierController::destroy` 守卫补 `DeletionGuard::referenced('outsourcing_orders', 'supplier_id', ...)`（同码 1109）。

配套测试：`SupplierTest::test_destroy_with_outsourcing_order_reference_fails`——构造 成品→BOM→工单→工序→委外单 完整外键链后删除供应商 → 1109。全量 375 单测全绿。
